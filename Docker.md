# Docker

Docker - это инструмент для упаковки приложения и его зависимостей в изолированную среду (контейнер), которая работает одинаково на любом компьютере или сервере.

## Образ и Контейнер
Это два главных понятия в Docker. Их легко перепутать, но разница принципиальна.
*   **Образ (Image):** Это статичный «слепок» или чертеж. Он содержит в себе операционную систему, код приложения и все библиотеки. Образ нельзя изменить (он Read-Only). Его можно только скачать (из реестра) или собрать.
*   **Контейнер (Container):** Это запущенный экземпляр образа. Когда ты запускаешь образ, Docker создает поверх него тонкий слой для записи, и получается контейнер. Контейнер можно остановить, удалить, перезапустить.

**Аналогия:** Образ — это класс в программировании. Контейнер — это объект этого класса. Или: Образ — это установочный диск с игрой, а контейнер — это запущенная игра.

## Слои (Layers)
Образ состоит из слоев. Каждая инструкция в `Dockerfile` (например, «установить Python» или «скопировать файл») создает новый слой. Docker кэширует эти слои. Если ты поменяешь код приложения, Docker не будет пересобирать всю систему заново, он возьмет готовые слои из кэша и пересоберет только последний. Это экономит время.

## Dockerfile
Это текстовый файл с инструкциями по сборке образа.
*   `FROM`: Базовый образ (например, `FROM ubuntu` или `FROM python:3.9`). С него начинается любой Dockerfile.
*   `WORKDIR`: Рабочая директория внутри контейнера (куда мы переходим).
*   `COPY`: Копирует файлы с твоего компьютера в контейнер.
*   `RUN`: Выполняет команды во время сборки образа (например, `RUN apt-get update` или `RUN pip install -r requirements.txt`).
*   `CMD`: Команда, которая выполнится при запуске контейнера (например, `CMD ["python", "app.py"]`).

## Основные команды Docker
*   `docker pull <имя_образа>` - Скачать образ из репозитория (Docker Hub).
*   `docker build -t <имя_образа> .` - Собрать образ из Dockerfile, который лежит в текущей директории (точка в конце).
*   `docker images` - Показать список всех локальных образов.
*   `docker run <имя_образа>` - Создать и запустить контейнер из образа.
    *   `docker run -d <имя>` - Запустить в фоне (detached).
    *   `docker run -p 8080:80 <имя>` - Пробросить порт 80 контейнера на порт 8080 хоста.
    *   `docker run -it <имя> bash` - Запустить интерактивно и открыть терминал (bash).
*   `docker ps` - Показать запущенные контейнеры.
*   `docker ps -a` - Показать все контейнеры (включая остановленные).
*   `docker stop <id_контейнера>` - Остановить контейнер.
*   `docker rm <id_контейнера>` - Удалить контейнер.
*   `docker rmi <имя_образа>` - Удалить образ.

## Docker Compose
Если у тебя сложное приложение (например, веб-сервер, база данных и кэш), запускать каждый контейнер вручную командой `docker run` неудобно. Для этого используется **Docker Compose**.
Это файл `docker-compose.yml`, где описываются все сервисы (контейнеры), их порты, тома (volumes) и зависимости. Запускается одной командой: `docker-compose up`.

## Контейнеры vs Виртуальные машины (ВМ)
*   **ВМ (Hyper-V, VMware):** Каждая ВМ запускает свою полноценную операционную систему. Это тяжело, долго грузится и съедает много ресурсов (RAM, CPU).
*   **Контейнеры (Docker):** Используют ядро хост-системы. Они не запускают свою ОС, а используют изоляцию пространств имен (namespaces) и контроль групп (cgroups). Поэтому контейнер весит мегабайты, а не гигабайты, и запускается за секунды.

## Безопасность в Docker
Контейнер изолирован от хост-системы, но эта изоляция не абсолютна. Главные правила:
*   Не запускайте контейнеры от пользователя `root`. Используйте директиву `USER` в Dockerfile.
*   Не храните пароли и ключи внутри образа (они останутся в слоях). Используйте переменные окружения или секреты (Secrets).
*   Регулярно обновляйте базовые образы (в них могут быть уязвимости).
