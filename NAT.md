# NAT

**NAT (Network Address Translation)** - это механизм, который позволяет устройствам с «серыми» (приватными) IP-адресами выходить в интернет под одним «белым» (публичным) IP-адресом. Это решает проблему нехватки IPv4-адресов и скрывает внутреннюю сеть от внешнего мира.

## Как это работает
Устройство внутри сети (например, виртуалка) отправляет запрос в интернет. Маршрутизатор подменяет IP-адрес отправителя с серого на свой белый и запоминает это в таблице NAT. Ответ из интернета приходит на белый IP. Маршрутизатор смотрит в таблицу NAT и передает ответ нужному устройству.

## Настройка NAT в Windows (Hyper-V)
В Hyper-V нет встроенного переключателя NAT. Его нужно создавать вручную через PowerShell.

Создаем виртуальный коммутатор: `New-VMSwitch -Name "My-Lab" -SwitchType Internal`

Назначаем IP-адрес для шлюза. В названии интерфейса есть круглые скобки, поэтому их нужно экранировать обратным апострофом (клавиша Ё): `New-NetIPAddress -IPAddress 192.168.100.1 -PrefixLength 24 -InterfaceAlias "vEthernet `(My-Lab`)"`

Создаем NAT-сеть: `New-NetNat -Name "My-Lab-NAT" -InternalIPInterfaceAddressPrefix 192.168.100.0/24`

Внутри виртуалки (например, в Ubuntu) вручную задаем IP из этой подсети (например, `192.168.100.10`), маску `255.255.255.0` и шлюз `192.168.100.1`.

## Настройка NAT в Linux (через терминал)
В Linux NAT настраивается через утилиту `iptables`. Это часто делают на маршрутизаторах или шлюзах.

Включаем форвардинг пакетов: `echo 1 > /proc/sys/net/ipv4/ip_forward` (чтобы это сохранилось после перезагрузки, нужно прописать `net.ipv4.ip_forward=1` в файле `/etc/sysctl.conf`).

Настраиваем правило MASQUERADE (оно подменяет IP-адрес отправителя на IP внешнего интерфейса): `iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE`

Разрешаем форвардинг в iptables: `iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT` и `iptables -A FORWARD -i eth0 -o eth1 -m state --state RELATED,ESTABLISHED -j ACCEPT`

## Настройка сети в Linux (через графический интерфейс)
В Ubuntu и большинстве дистрибутивов с GNOME или KDE используется менеджер сети NetworkManager. Он позволяет настроить подключение (включая статический IP и шлюз) без ввода команд.

Откройте меню приложений и перейдите в Настройки (Settings). Найдите раздел Сеть (Network) или Wi-Fi. Выберите нужное подключение и нажмите на шестеренку (Настройки). В открывшемся окне перейдите на вкладку IPv4. Выберите метод Вручную (Manual). Здесь вы можете задать статический IP-адрес (Address), маску подсети (Netmask) и шлюз (Gateway). На вкладке DNS пропишите адрес DNS-сервера (например, `8.8.8.8`). После ввода данных нажмите Применить (Apply). Сеть перезапустится с новыми параметрами.

## Проброс портов (Port Forwarding)
Используется, чтобы обеспечить доступ извне к скрытым за NAT устройствам.

В Windows (PowerShell): `Add-NetNatStaticMapping -NatName "My-Lab-NAT" -Protocol TCP -ExternalIPAddress 0.0.0.0 -ExternalPort 8080 -InternalIPAddress 192.168.100.10 -InternalPort 80`

В Linux (iptables): `iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 192.168.100.10:80`

## Почему это важно для ИБ
* **Скрытность:** NAT прячет внутреннюю структуру сети от сканеров из интернета.
* **Анализ логов:** В логах ты будешь видеть только белый IP шлюза. Чтобы понять, какой именно внутренний пользователь натворил дел, нужно смотреть таблицу NAT.
* **Виртуалки:** Понимание NAT позволяет безопасно разворачивать тестовые стенды (как мы делали с Wazuh), не боясь «засветить» их в домашней сети.
