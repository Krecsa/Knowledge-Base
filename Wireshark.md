# Wireshark

Wireshark — это сетевой анализатор трафика. 

## Что такое SYN-пакеты и как они связаны с атаками

**TCP Handshake (Тройное рукопожатие)** — это процесс установки соединения в протоколе TCP. Он состоит из трех шагов:
1. **SYN (Synchronize):** Клиент отправляет пакет с флагом SYN, предлагая серверу установить соединение.
2. **SYN-ACK (Synchronize-Acknowledge):** Сервер отвечает с флагами SYN и ACK, соглашаясь на соединение.
3. **ACK (Acknowledge):** Клиент подтверждает получение ответа.

**Как это выглядит в атаках (SYN Scan):**
Хакеры используют сканеры (например, Nmap), чтобы проверить, какие порты открыты на сервере. Они отправляют **много SYN-пакетов** на разные порты. 
* Если сервер отвечает **SYN-ACK** — порт открыт.
* Если сервер отвечает **RST** (Reset) — порт закрыт.
В логах Wireshark это выглядит как шквал `SYN`-пакетов от одного IP к сотням портов или хостов за короткое время.

**Как это выглядит в нормальной работе:**
Обычно ты видишь SYN, затем SYN-ACK, затем ACK (3 пакета), после чего начинается передача данных (HTTP, HTTPS, SMB). Если ты видишь много повторяющихся SYN без ответа (Retransmission) — значит, на том конце проблемы с сетью или сервер недоступен.

## Базовые фильтры (Что вводить в строку поиска)

*   **`ip.addr == 172.20.30.17`** — показывает весь трафик (и входящий, и исходящий) для этого IP.
*   **`ip.src == 172.20.30.17`** — показывает только пакеты, которые **исходят** от этого IP (кто атакует).
*   **`ip.dst == 172.20.30.17`** — показывает только пакеты, которые **приходят** на этот IP.
*   **`tcp.flags.syn == 1`** — показывает только пакеты с флагом SYN (полезно для поиска сканирований).
*   **`arp`** — показывает ARP-запросы (используется для поиска активных хостов в локальной сети и ARP-спуфинга). APR-запрос - это широковещательное сообщение, которое отправляет устройство в локальной сети, чтобы узнать MAC-адрес другого устройства по его IP-адресу. 
*   **`http.request.method == "GET"`** — показывает только GET-запросы.

## Как найти MAC-адрес отправителя

1.  Выбери пакет в списке.
2.  В нижней панели (где подробности пакета) раскрой ветку **Ethernet II**.
3.  Поле **Source** (Src) — это MAC-адрес отправителя. Поле **Destination** (Dst) — MAC-адрес получателя.

## Как найти Session ID (Идентификатор сессии)

Если анализируешь SMB или RPC трафик:
1.  Выбери пакет.
2.  В нижней панели раскрой ветку **SMB2** (или **DCERPC**).
3.  Ищи поле **Session ID** или **Tree Connect**.

## Что важно для SOC

1.  **Сканирование портов** — это шквал SYN-пакетов от одного IP. Wireshark отлично показывает это визуально.
2.  **ARP-спуфинг** — если ты видишь, что один и тот же MAC-адрес отвечает за разные IP-адреса в ARP-ответах, это подмена.
3.  **Аномалии в трафике** — например, передача больших объемов данных на неизвестный внешний IP (эксфильтрация).
4.  **Чтение пакетов** — ты можешь открыть любой пакет и увидеть его содержимое (если трафик не зашифрован). Это полезно для анализа вредоносных запросов (например, видно, что малварь стучится на конкретный URL).
