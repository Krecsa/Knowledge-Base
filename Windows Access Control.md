# Управление доступом в Windows

## Субъекты и объекты доступа
В основе безопасности Windows лежит концепция доступа. **Субъект** - тот, кто запрашивает доступ, может быть пользователем, процессом или системой. **Объект** - то, к чему запрашивается доступ (файл, папка, принтер, раздел реестра). Набор действий, которые субъект может выполнить над объектом, называется **привилегиями** или полномочиями.

## Модели разграничения доступа
В Windows на практике применяется комбинация двух основных моделей.

### Дискреционное управление доступом (DAC)
Права на объект определяет его владелец. В Windows это реализуется через **DACL (Discretionary Access Control List)** - список избирательного управления доступом, который хранится в дескрипторе безопасности объекта. Каждая запись в DACL (ACE) содержит SID пользователя или группы и набор разрешенных или запрещенных действий (чтение, запись, выполнение).

Ключевая особенность DACL: **запрет имеет приоритет над разрешением**. Если пользователь одновременно входит в группу, которой доступ разрешен, и в группу, которой доступ запрещен, доступ будет заблокирован.

> Всё, что не разрешено, автоматически запрещено.

### Ролевое управление доступом (RBAC)
Права назначаются не конкретному пользователю, а **роли** (группе), которая соответствует должности сотрудника. Пользователя включают в группу, и он автоматически получает все права этой группы. В Windows это реализуется через группы безопасности Active Directory и групповые политики (GPO).

> Мандатное управление доступом (MAC, где права зависят от меток конфиденциальности) в стандартной Windows не реализовано. Его используют отдельные программные комплексы (например, средства защиты информации).

## Идентификаторы безопасности (SID)
Каждая учетная запись в Windows имеет уникальный **SID (Security Identifier)**. Это не просто имя пользователя, а структура, которая используется системой для проверки прав.

Формат SID: `S-1-5-21-X-Y-Z-RID`
* **S** - идентификатор (всегда S).
* **1** - версия (всегда 1).
* **5** - источник (NT Authority, то есть Windows).
* **21** - указывает, что SID выдан компьютером или доменом.
* **X-Y-Z** - уникальные числа, сгенерированные при установке системы (идентификатор машины/домена).
* **RID (Relative ID)** - относительный идентификатор, уникальный номер учетной записи внутри этой машины/домена.

**Важные RID для ИБ:**
* **500** - встроенная учетная запись **Администратор** (Administrator). Она существует всегда, даже если переименована.
* **501** - встроенная учетная запись **Гость** (Guest).
* **1000 и выше** - обычно начинаются RID для обычных создаваемых пользователей.

## Маркеры доступа и дескрипторы безопасности
Когда пользователь входит в систему, создается его **маркер доступа (Access Token)**. Этот маркер прикрепляется к каждому процессу, запущенному от имени этого пользователя. В маркере содержится SID пользователя, SID групп, в которые он входит, и список его привилегий.

Каждый защищаемый объект (файл, папка) имеет **дескриптор безопасности (Security Descriptor)**. Он содержит:
* **Owner** - SID владельца объекта.
* **DACL** - список того, кому и что можно делать (разрешения).
* **SACL** - список того, какие действия с объектом нужно записывать в журнал аудита (для расследований).

Когда процесс пытается открыть файл, система сравнивает SID из маркера доступа процесса с записями в DACL файла. Если есть разрешение (и нет запрета) - доступ открывается.

## Контроль учетных записей (UAC)
**UAC (User Account Control)** - это механизм, который не дает приложениям автоматически получать права администратора.

Даже если пользователь входит в группу «Администраторы», при входе в систему ему выдается **два маркера доступа**: один обычный (Standard User) и один с правами администратора (Administrator). Все программы по умолчанию запускаются с обычным маркером.

Когда программе (или пользователю) нужны права администратора, срабатывает UAC. Появляется окно подтверждения, которое обрабатывает процесс **`consent.exe`**. Он работает от имени системы (SYSTEM) и показывает запрос на защищенном рабочем столе. Если пользователь подтверждает (вводит пароль или нажимает «Да»), процессу передается административный маркер доступа.

Злоумышленники часто пытаются обойти UAC (UAC Bypass), чтобы повысить привилегии без ведома пользователя. Легитимные способы повышения прав, которые они могут использовать:
* Утилита `runas.exe` (запуск от имени другого пользователя).
* Контекстное меню «Запуск от имени администратора» (Run as administrator).
* «Запуск от имени другого пользователя» (Run as different user) через Shift + правый клик.
